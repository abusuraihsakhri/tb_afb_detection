Workflow

From microscopy image to reviewed candidates

The repository separates data preparation, model training, inference, post-processing, and human review.

01

Tile extraction

OpenSlide-native WSI extraction and OpenCV raster fallback generate fixed-size research tiles.

02

Training

Ultralytics YOLO training supports CPU, CUDA, or Apple MPS when available in the installed PyTorch build.

03

Inference

Sliding-window inference translates tile detections to slide coordinates and applies global post-processing.

04

Annotation

The local browser interface stores normalized YOLO annotations into train and validation splits.

Architecture

Why the application itself is not hosted on Pages

GitHub Pages serves this static project site. The computational application remains local because its primary workflow requires a Python API process, PyTorch/Ultralytics, native OpenSlide libraries, local files and model checkpoints, and potentially large whole-slide images.

Pages therefore documents and showcases the project without pretending to execute the backend in-browser.

Validation boundary

Candidate detection is not smear grading

Model and heuristic outputs are candidate detections for expert review. The inference workflow deliberately does not convert model candidates into WHO/IUATLD smear grades.

The repository includes a separate grading utility for confirmed microscopy counts when an appropriate examined-field protocol is available.

Included safeguards

  • Bounded HTTP body and decoded-image sizes
  • Path containment for configured data roots
  • Normalized annotation bounds validation
  • Localhost-first service defaults
  • Training trigger disabled by default
  • Dependency auditing in CI

Run the local API

python -m uvicorn 05_DEPLOYMENT.api.server:app \
  --host 127.0.0.1 --port 8001

http://127.0.0.1:8001/ui/

python 02_CODE/scripts/check_data_integrity.py
