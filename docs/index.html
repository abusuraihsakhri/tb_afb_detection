Implementation workflow

How the repository processes images

The website mirrors the actual code paths without pretending that GitHub Pages can execute the server-side model.

01

Image / WSI loading

Raster images use OpenCV. Supported whole-slide formats use OpenSlide for level-aware access.

data/wsi_loader.py
02

Tiling

Large slides are divided into bounded tiles so inference can run at manageable spatial and memory scales.

01_extract_tiles.py
03

Candidate detection

An AFB-trained YOLO checkpoint can score candidate bacilli. The local web app labels heuristic fallback explicitly.

models/yolo_detector.py
04

Post-processing

Detections are filtered by confidence, class, morphology, and overlap before being translated to slide coordinates.

inference/postprocessor.py
05

Human review

Candidate boxes remain research outputs for expert review, annotation, correction, and downstream validation.

static/annotate.html

Architecture

What runs on GitHub Pages—and what does not

GitHub Pages hosts this static demonstration because it is HTML, CSS, JavaScript, and Canvas only. The actual detection application stays local/server-side because it depends on PyTorch, Ultralytics, native OpenSlide libraries, model checkpoints, local files, and potentially very large WSIs.

This separation keeps the public project website lightweight while preserving the real research pipeline in the repository.

Validation boundary

Candidate detection is not a TB diagnosis

The repository intentionally separates model-generated candidates from smear grading. Candidate counts are not automatically converted into a WHO/IUATLD grade. The grading utility is intended for confirmed microscopy counts with an appropriate examined-field protocol.

Important limitations

  • No validated AFB-specific checkpoint is committed to the repository.
  • The included yolov8n.pt is generic initialization material, not a diagnostic model.
  • The Pages demonstration uses synthetic data and fixed illustrative scores.
  • Real WSI processing requires the local Python/OpenSlide environment.
  • Clinical deployment would require independent validation, governance, and regulatory review.
